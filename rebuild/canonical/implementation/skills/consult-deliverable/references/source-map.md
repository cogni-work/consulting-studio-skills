# Operational requirements for usable deliverables

| Requirement | Apply it in the deliverable |
| --- | --- |
| [Results contract](../../consult-results/references/output-contract.md) | Consume exact Result/evidence and supported/refuted/open findings with all qualifications; compatible supplied results replace invocation. |
| [Delivery journey](../../../../docs/architecture/journey.md#7-review-submit-accept-and-close) | Turn the supported answer into the agreed form, with criterion coverage, usability, exact-version review and separate release/acceptance decisions. |
| [Business objects](../../../../docs/architecture/business-objects.md#delivery-objects) | Keep stable Deliverable, Baseline, Result and Artifact identities and distinguish content from inspected rendered form. |
| [Evidence](../../../../docs/architecture/knowledge.md#evidence-that-can-be-defended) | Preserve passage/coverage/use basis, contrary statements, human originals and every substantive claim's dependencies. |
| [Communication craft](../../../../docs/architecture/communication.md#communication-craft-from-evidence-to-understanding) | Adapt sponsor/operating explanations and objections without changing support; bind exact design, values/derivation, encoding and requested medium for production. |
| [Decisions](../../../../docs/architecture/decisions.md#decisions-at-their-actual-triggers) | Human review, release/submission, acceptance/reservations, invoice/payment and achieved outcome remain distinct and version-specific. |
| [Production](../../publishing-render/references/output-contract.md) and [inspection](../../publishing-inspect/references/output-contract.md) | Delegate only through an actually available authorized route; an outline or graphic specification retains its incomplete status. |
| [Correction](../../../contracts/entity-lineage.md) | Preserve issued/accepted/reserved versions; identify affected storyline, graphics, recommendations, criteria, handoff and checks when bytes change. |

A missing evidenced cost table remains a criterion gap even if other content is
accepted. Report content and deck outline cannot complete a promise requiring
rendered, inspected files. A changed-source correction can revise the current
answer without silently replacing an earlier baseline or acceptance reservation.

Read only the references needed for the selected task. Apply their current adopted
requirements within the actual audience, purpose and available authorized operations.
A method dependency names compatible information; it does not require a prior skill
invocation. Retain exact source versions and content identities when consuming outputs.
