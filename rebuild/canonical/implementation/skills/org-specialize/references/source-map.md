# Specialization requirements

Use this map with the [specialization contract](output-contract.md).

| Requirement | Operational application |
| --- | --- |
| [Market and firm requirements](../../../../docs/architecture/knowledge.md#market-and-firm-domain-requirements) | Use the explicitly selected geography, client breadth and service focus. Bind each applicable requirement to exact source bytes, scope, responsible owner and named skills. |
| [Personal and shared homes](../../../../docs/architecture/knowledge.md#personal-and-shared-homes), [bindings](../../../workspace-bindings/contract.md) | Keep personal preferences personal; check current actor, audience, purpose, source rights and actual operations. A home or readable setting grants no authority or content access. |
| [Communication requirements](../../../../docs/architecture/communication.md) | Resolve firm design/client form conflicts through their owners; preserve semantic labels, distinctions beyond color and exact supplied applicability decisions. |
| [Correction and dependent uses](../../../../docs/architecture/knowledge.md#correction-and-dependent-uses), [entity lineage](../../../contracts/entity-lineage.md) | Compare actual before/after rows and target bytes, identify affected skills/rechecks and preserve issued work, human originals and incomplete dependency coverage. |
| [Core, adaptation and instance](../../../../docs/product/deployment-service.md#core-adaptation-and-live-instance) | Keep common methods separate from customer configuration. A bespoke extension is a separately scoped proposal with its own ownership, rights, acceptance and maintenance decisions. |

Supplied inputs permit useful preparation without mandatory discovery or storage.
Actual adoption requires the responsible owner's current exact decision and a
supported authorized settings save/readback. Synthetic authority remains synthetic;
no preparation or local check establishes law, firm policy, integration or acceptance.
