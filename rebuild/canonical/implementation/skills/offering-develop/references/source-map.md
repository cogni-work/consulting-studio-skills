# Offering-development requirements

Use this map with the [offering-development contract](output-contract.md).

| Requirement | Operational application |
| --- | --- |
| [Commercial objects and decisions](../../../../docs/architecture/business-objects.md) | Keep the optional versioned offering, exact prior proposal references and responsible offering owner's choice distinct. Both modes produce proposals only. |
| [Portfolio and later outcomes](../../../../docs/product/acceptance.md#a13-portfolio-and-later-outcome-checks) | A first offering needs no prior engagement. Preserve hypotheses, price/team gaps, bounded market-test criteria and the owner's adoption decision. |
| [Learning into the next offer](../../../../docs/architecture/journey.md#8-learn-into-the-next-offer), [closure](../../consult-closure/SKILL.md) | Use only exact permitted lesson surfaces. Keep buyer reasons separate from firm interpretation and unassessable outcomes explicit; closure grants no client-material reuse. |
| [Knowledge boundaries](../../../../docs/architecture/knowledge.md), [entity lineage](../../../contracts/entity-lineage.md), [bindings](../../../workspace-bindings/contract.md) | Check all owners' current rights, exact carrier/surface bytes and clocks. Preserve revocation, unread-current blockers, late dissent, corrected dependencies and uncertain effects without blind retry. |
| [Communication](../../../../docs/architecture/communication.md) | Return a concise useful draft with qualifications and settling questions; keep the internal assessment separate from the bounded reusable payload. |

Prior proof selection supplies no new permission. Actual target adoption, storage,
transfer, market testing and owner acceptance need their own current evidence and
authority. Illustrative examples establish no law or live instance requirements.
