# Optional synthetic example — coordination brief

This entire dataset is fictional and reusable for an explicitly selected Setup
example. It contains no real client facts, private identities or live bindings.
It is optional: skipping it leaves normal projects empty and permits ordinary use
with user-provided or authorized content. Never automatically populate a normal
project, home, settings record or knowledge base from this file.

## Source-free S installation check

Choose this separate small workflow for S-SESSION when no external/source retrieval
is in scope. Invoke the installed `structure-problem` method with its actual
required resource reads, rather than answering from this example alone:

> Synthetic example — unaccepted. A fictional consulting team wants to reduce
> weekly workshop preparation from three hours to two within four weeks. The
> cause of the current effort is unknown. Frame an answerable diagnostic question,
> a small set of distinct enquiry parts and the next evidence needed. Chat-only;
> no research, external sources, saved record or business decision is requested.

Success means a versioned scoping draft keeps these figures as fictional input,
uses stable question/part references and a named cutting principle, preserves the
unknown cause, proposes scope and settling tests with owners/dates unknown where
unsupplied, and identifies the next human decision. Inspect its actual output;
this prompt contains no expected answer. It proves no measured saving, retention,
client admission or human acceptance. Record input as synthetic user instructions,
with no documentary source test. This is separate from the two-passage source-test
example below and from repository simulations; it requires no connector or storage.

## Two-passage source-test request

Using only the two passages below, prepare a short coordination brief for the
fictional project lead: what do we know about the weekly handover, what remains
uncertain, and what should the lead clarify before changing it? Cite each passage
by its label. Preserve the disagreement and distinguish a proposal from a decision.

The default example output is a chat-only draft labelled **Synthetic example —
unaccepted**. Retention requires a separately selected clearly labelled test home,
concrete content/destination authority and the applicable supported save/readback.
Choosing this dataset grants none of those effects and makes no production grant.

## Example source A — fictional team note, revision 1

The fictional team currently holds a handover meeting every Friday. The team lead
proposes replacing it with a shared weekly note because some colleagues cannot
attend. No change has been approved. The note does not measure attendance, time
spent, decision speed or delivery outcomes.

## Example source B — fictional colleague comment, revision 1

A colleague says the Friday discussion helps resolve ambiguous dependencies and
objects to replacing it before the team agrees how questions will be answered.
The colleague suggests testing a written update alongside the discussion first.
The project sponsor has not yet responded. This is one colleague's view, not a
measured finding or an authorized decision.

## Bounded success criterion

The brief traces its factual statements to these passages, retains the objection,
identifies absent measurements and sponsor decision, and proposes a focused next
question without inventing a benefit, approval, commitment or external action.
This criterion is an inspection aid, not a prewritten result or evidence that any
method, host operation, retention, human review, release or acceptance passed.
If a presentation is selected instead, apply the normal request-bound narrative
choice, evidence/graphics, rendering and inspection requirements before production.
