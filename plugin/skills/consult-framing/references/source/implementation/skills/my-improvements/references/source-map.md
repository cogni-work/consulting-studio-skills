# Product improvement requirements

Use the exact readable canonical baseline for the proposal. Authenticate its commit,
tree and document bytes through the available authorized Git route. A working copy,
summary or self-declared digest cannot substitute for the governing document. An
unread or mixed baseline blocks only its dependent comparison; permitted problem
framing can continue.

| Operational reference | Apply in this method |
| --- | --- |
| [Common requirements](../../../runtime/requirements.md) | Preserve the request, selected domain scope, human authority and actual information-use permissions. Distinguish personal preferences, firm rules and common product proposals. |
| [Output contract](output-contract.md) | Produce concrete proposed wording and exact diff, traceable affected passages/criteria, decision owner, alternatives, dissent and remaining choices. Reconcile the old proposal with the actual current baseline. |
| [Binding contract](../../../workspace-bindings/contract.md) | Resolve current read and outgoing audience/use permissions separately. Technical read access never implies sharing or retention. |
| [Binding catalog](../../../runtime/binding-catalog.json) | Use only selected sanitized feedback drafts and the minimum relevant canonical material; do not inspect unrelated private inventory. |
| [Entity lineage](../../../runtime/entity-lineage.md) | Bind exact revisions, permission/provenance envelopes, input/output hashes and affected uses. Distinguish proposed impacts from observed changes. |
| [Storage lifecycle](../../../runtime/storage-lifecycle.md) | Use fresh versioned outputs, preserve human originals and prior receipts, and inspect uncertain effects before retry. |

Validate nonempty path/passage/scenario references against the authenticated
documents and actual criteria at that baseline. Resolve exactly one marked proposal
anchor regardless of document order. Compare the complete governing identity set;
missing, duplicated or substituted documents cannot establish coverage. Verify
proposed additions and exact diffs against the selected permitted input fields.

Keep the complete supplied decision owner and exact target basis. A fictional owner
preference remains fictional preparation context; it cannot approve canonical wording.
Permit independently supplied text from an authorized contributor without exposing
a denied contributor's identity. A stable proposal label is distinct from its
content revision. A source merge, owner adoption, actual workflow update and human
acceptance each need their own exact-scope evidence.
